# Security Policy

## Supported versions

Sw3 is pre-1.0. Only the latest tagged release on `main` receives security
updates.

| Version | Supported |
|---------|-----------|
| `main`  | ✅        |
| `< latest` | ❌     |

## Reporting a vulnerability

**Please do not open public GitHub issues for security vulnerabilities.**

If you believe you've found a security issue in Sw3 — including in the
Solidity contracts (`contracts/`), the execution engine, the auth flow, or
any service that handles signed messages or private keys — please report it
privately via one of the following:

1. **GitHub private security advisory** (preferred):
   <https://github.com/lackx741-tech/Sw3/security/advisories/new>
2. Email the maintainers (see repo `OWNERS` or the GitHub org page).

Please include:

- A description of the vulnerability and its impact
- Steps to reproduce (or a proof-of-concept)
- The commit hash you tested against
- Your name / handle for credit (optional)

We aim to acknowledge reports within **72 hours** and to provide a fix or
mitigation timeline within **7 days** for critical issues.

## Scope

In-scope:

- Smart contracts under `contracts/` (sweeper, fee-router, eip7702, multicall)
- Authentication and session handling (SIWE, JWT)
- Transaction signing / batching paths in `packages/sdk` and
  `services/execution-engine`
- RPC routing and mempool listening services
- The integration script generated by `apps/dashboard`

Out of scope:

- Issues in third-party dependencies — please report upstream, but feel free
  to also let us know
- Findings against local-dev defaults (`.env.local.example`, dev JWT secrets)
- Denial-of-service via unrealistic load on local stacks

## Disclosure

We follow coordinated disclosure. Once a fix is released, we will publish an
advisory and credit the reporter (unless anonymity is requested).
